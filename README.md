# FreeMoCap Validation

This repository contains the analysis and reproducibility pipeline for the FreeMoCap validation study. 

Simply put, this pipeline makes transparent all of the analyses used for the gait and standing balance analyses in the paper, and will also regenerate the figures and tables reported in the study from the publicly released validation dataset. 

-- *What does the dataset contain?*

The validation dataset contains aligned 3D trajectory data from six participants collected during treadmill gait and standing balance tasks. The dataset contains the 3D data (stored in parquet format) for each subject for 3 FreeMoCap reconstructions (derived using MediaPipe, RTMPose, and ViTPose), and the joint centers calculated from Qualisys marker data, which was used as a reference. 

The public dataset is archived on Zenodo:

**FreeMoCap Validation Dataset: Multi-Camera Markerless Motion Capture of Treadmill Gait and Standing Balance**  
**Version:** 1.0  
**DOI:** 10.5281/zenodo.23041223

## Quick start

This quick start goes over how to use this repository to download the dataset, run all the analyses, and regenerate all tables and figures. For more detailed information on what the dataset contains, see below. 

### Requirements

- Git (or your preferred Github repo manager)
- [uv](https://docs.astral.sh/uv/getting-started/installation/)
- Python 3.11

Clone the repository and enter the project directory:

```bash
git clone https://github.com/freemocap/validation.git
cd validation
```

Install the reproducible project environment:

```bash
uv sync
```

Download the public validation dataset:

```bash
uv run validation download-data
```

Run the validation analyses:

```bash
uv run validation run
```

Build the artifact database used by the plotting scripts:

```bash
uv run validation build-db
```

Generate all study figures and tables:

```bash
uv run validation plot-all
```

The complete reproduction workflow is therefore:

```bash
uv sync
uv run validation download-data
uv run validation run
uv run validation build-db
uv run validation plot-all
```

This workflow has been tested using version 1.0 of the published Zenodo dataset.

## What the commands do

### `download-data`

```bash
uv run validation download-data
```

Downloads the six participant archives from the published Zenodo record, verifies their SHA-256 checksums, and extracts them into:

```text
freemocap_validation_dataset/
├── README.md
├── SHA256SUMS.txt
└── data/
    ├── sub-001/
    ├── sub-002/
    ├── sub-003/
    ├── sub-004/
    ├── sub-005/
    └── sub-006/
```

The downloaded dataset is excluded from Git.

### `run`

```bash
uv run validation run
```

Runs the validation analysis pipeline across the trial configurations in `configs/`.

The pipeline reads the aligned 3D trajectory data from the downloaded dataset and generates the derived gait and balance analysis outputs required by the study.

By default, the command uses:

```text
freemocap_validation_dataset/data/
```

as the dataset root.

### `build-db`

```bash
uv run validation build-db
```

Indexes the generated validation artifacts into a local SQLite database:

```text
validation.db
```

The database provides a common index used by the study-level plotting and table-generation scripts.

### `plot-all`

```bash
uv run validation plot-all
```

Runs the complete set of gait and balance plotting and table-generation scripts.

Generated study-level outputs are written under:

```text
outputs/
├── figures/
├── tables/
└── analyses/
```

Figures are saved without being displayed by default.

To display figures as they are generated:

```bash
uv run validation plot-all --show
```

To generate only balance outputs:

```bash
uv run validation plot-all --section balance
```

To generate only gait outputs:

```bash
uv run validation plot-all --section gait
```

## Dataset

The public validation dataset contains data from six participants, each completing:

- Two treadmill gait trials containing multiple walking-speed conditions
- Two standing balance trials containing Eyes Open/Closed × Solid/Foam conditions

This results in 24 trials in total.

For each trial, aligned 3D trajectory data are provided for:

- MediaPipe
- RTMPose
- ViTPose
- Qualisys marker-based reference

Within each tracking system, the canonical input file is:

```text
aligned_3d_data/
└── freemocap_data_by_frame.parquet
```

The public dataset contains the aligned trajectory data used as inputs to the validation analyses. Derived analysis outputs, figures, and tables are generated by this repository rather than distributed as part of the dataset.

The dataset does not include raw video recordings or directly identifying participant information.

For the full dataset description, structure, versioning information, and license, see the Zenodo record:

**DOI:** 10.5281/zenodo.23041223

## Repository structure

The main components of the repository are:

```text
validation/
├── configs/                  # Trial-specific validation configurations
├── database/                 # Artifact indexing and database utilities
├── plotting/                 # Study figure and table generation
│   ├── balance/
│   └── gait/
├── qualisys_markerset/       # Qualisys model information
├── tests/                    # Automated tests
├── validation/               # Validation pipeline and command-line interface
├── pyproject.toml            # Project dependencies and configuration
├── uv.lock                   # Locked dependency environment
└── README.md
```

After downloading the dataset and running the complete reproduction workflow, the working directory will additionally contain:

```text
validation/
├── freemocap_validation_dataset/
│   └── data/
├── outputs/
└── validation.db
```

These generated/downloaded resources are excluded from Git.

## Validation configurations

Trial-specific configuration files are stored under:

```text
configs/
└── sub-XXX/
    └── task-<task>_trial-<run>.yaml
```

These configurations define the processing parameters required to reproduce the analyses for each trial.

For standing balance trials, the configurations also define the frame ranges corresponding to the four experimental conditions:

- Eyes Open / Solid Ground
- Eyes Closed / Solid Ground
- Eyes Open / Foam
- Eyes Closed / Foam

Keeping these annotations in the trial configurations makes the analysis inputs explicit and version-controlled.

## Advanced usage

The default commands are intended to reproduce the study without requiring path configuration. Additional CLI options are available for development, testing, or use with a dataset stored elsewhere.

To see the available commands:

```bash
uv run validation --help
```

For options associated with a specific command:

```bash
uv run validation download-data --help
uv run validation run --help
uv run validation build-db --help
uv run validation plot-all --help
```

### Custom download location

By default, the dataset is downloaded to:

```text
freemocap_validation_dataset/
```

A different location can be specified with:

```bash
uv run validation download-data --destination <dataset-directory>
```

When using a custom location, supply its `data/` directory to the analysis and database commands:

```bash
uv run validation run --dataset-root <dataset-directory>/data
uv run validation build-db --dataset-root <dataset-directory>/data
```

For example:

```bash
uv run validation download-data --destination D:/datasets/freemocap_validation_dataset
uv run validation run --dataset-root D:/datasets/freemocap_validation_dataset/data
uv run validation build-db --dataset-root D:/datasets/freemocap_validation_dataset/data
uv run validation plot-all
```

### Running selected trackers

The analysis can be restricted to one or more pose-estimation backends using `--tracker`:

```bash
uv run validation run --tracker mediapipe
```

Repeat the option to select multiple trackers:

```bash
uv run validation run --tracker mediapipe --tracker rtmpose
```

### Running selected trial configurations

A configuration filename pattern can be supplied with `--config-pattern`.

For example, to run only balance trials:

```bash
uv run validation run --config-pattern "*balance*.yaml"
```

Or only treadmill trials:

```bash
uv run validation run --config-pattern "*treadmill*.yaml"
```

## Reproducibility scope

This repository reproduces the validation analyses beginning from the aligned 3D trajectory data released in the public dataset.

The reproducibility workflow therefore covers the derivation of the gait and balance metrics, statistical analyses, figures, and tables from those trajectories. It does not reproduce pose estimation or 3D reconstruction directly from the original camera videos, because raw participant videos are not included in the public dataset.

The combination of the versioned Zenodo dataset, trial configuration files, locked Python environment, and analysis pipeline is intended to preserve the computational path from the released trajectory data to the reported validation results.
